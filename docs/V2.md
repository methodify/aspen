# Aspen v2 — the operator's switchboard

Synthesis of a six-agent swarm (two vision, three design languages, one UI
audit; raw proposals in the build history under `scratchpad/v2/`). This is
the spec the v2 console is built to.

## The thesis

Aspen is not a chat app with agents in it. It is **the observability and
control plane for a distributed system whose processes reason** — and the one
thing no single session can do for itself is *routing*: moving a decision or
context from one place to the others and watching it land. So the console
centers routing, presence, and the bus, not REST tables.

## Design language: "The Switchboard"

The only machines ever built for one person routing many live conversations
at once are switchboards, patch bays, ATC flight-strip racks, and mixing
desks. Aspen borrows that solved language for priority and presence. It reads
as **back-lit instrument steel**, not near-black; **color equals meaning**,
never a single decorative accent.

**Two independent color systems, kept apart:**

- **Priority** (the three delivery classes): gating `#FF3B57` (alarm red),
  normal `#FFB02E` (amber, the working color), notice `#35C2D1` (ambient
  cyan). Same three hues in the same roles everywhere — badge, row tab, bus
  capsule, compose selector — so the operator reads priority pre-consciously.
- **Presence** (turn-state): busy `#37E08B` (phosphor, streaming), idle
  `#8A9AA8` (lit steel), offline `#46545F` (flatline).

Base is blue-graphite (`--bg-base #0E141B`) layering *up into light*. Type:
**Chakra Petch** (squared engraved labels, always tracked, usually caps) +
**IBM Plex Sans** (body) + **IBM Plex Mono** (all ids, paths, counts,
timecodes — the telemetry voice). Square by default with an 8px machined
**chamfer** on strips/panels; a 2px hint only on capsules. Full token sheet,
light mode, and component CSS: the design system is implemented in
`ui/src/styles.css` (derived verbatim from these values).

**The signature — THE BUS.** A 6px illuminated light-rail, always in the same
place relative to the stage, down which every message travels as a
color-coded **capsule** patched to its row. Traffic — its volume, priority
mix, rhythm — is the primary visual, the way a switchboard operator watches
lamps, not text.

**Motion is assigned by class** (reduced-motion → instant state, never
information-only): gating *snaps* in and holds a slow alarm pulse until acked;
normal *seats* like a patched plug; notice *drifts* dim and never moves
layout. Presence is a live **carrier meter** (a VU bar that oscillates with
token throughput), never a static dot.

## Information architecture

Five attention-ordered surfaces replace the six flat REST pages:

1. **Command** (home) — the triage cockpit. NEEDS YOU (the operator inbox,
   actionable inline: allow/deny, reply, open), IN FLIGHT (the live activity
   feed — every session's presence + recent bus traffic on a shared time
   sense), and mesh health in the status bar. First screen, always.
2. **Conversations** — channels as first-class. A channel rail (auto `#repo`,
   custom, cross-node) → a thread rendered as a transcript with **inline
   delivery/ingest ticks** (who got it, who ingested it, at what class) → a
   context pane (members, nodes spanned, linked record). **New Channel** mixes
   agents, repos, and nodes. **Route…** fans a message across
   channels/sessions and shows every hop's delivery proven.
3. **Sessions** — master list (flight-strips by state) + the fully
   interactive session (streaming transcript, docked permission prompts,
   intercom compose with a class selector, step-in/return).
4. **Map** — the mesh as a place: nodes as regions, sessions as tracked
   contacts, channels as drawn edges, live traffic pinging along them.
5. **Library** — repos (remember, skip-permissions default, discover/resume
   sessions) and skills (edit + live reload).

A `⌘K` command palette and full keyboard patching run across all of them.

## Backend surface added for v2 (built + verified)

- **Custom channels**: `channels`/`channel_members` tables; explicit
  membership by address (`@agent`, `agent@node`, `@operator`) that can span
  repos and nodes. `GET/POST /api/channels`, `DELETE /api/channels/{n}`,
  `POST /api/channels/{n}/members[/remove]`, `GET /api/channels/{n}/log`.
- **Channel posts**: a fan-out to N members shares one `post` id, so a
  channel renders as one conversation with per-post delivery/ingest
  aggregates (not N rows).
- **Activity**: `GET /api/activity` — every session's derived turn-state and
  pending count (local + remote) plus the recent trail and the operator inbox
  count. Presence is derived from turn-state, so it cannot lie.
- Bus resolution honors custom channels; `bus_send` to a custom `#channel`
  fans out to its explicit members (forwarding cross-node ones).

## Build order

Design system + shell + shared components (BusRail, Capsule, Badge, Meter,
MessageRow, FlightStrip) → Command → Conversations (the #1 ask) → Sessions
(adapt) → Map → Library (merge Repos+Skills). Each surface uses the shared
design system so the identity stays coherent.

## v2.1 — closing the promise/product gap

A step-back audit against DESIGN.md and the founding conversation found the
console using only a fraction of the protocol's documented power. v2.1
closes it (backend verified live, including cross-node over the relay):

**Session parity**: AskUserQuestion answered for real (§7.6 answers ride
`updatedInput`), always-allow (echoing the CLI's `permission_suggestions`),
slash autocomplete from the handshake `commands[]`, model/mode switching,
the `get_context_usage` meter, operator titles + editable charters, and the
three render modes (chat / console / source) from the founding conversation.

**The real operator inbox**: `GET /api/needs` aggregates every open
permission prompt and question from every connected node (remote agents as
`name@node`, answerable through any node) plus @operator mail mesh-wide.
Command triages all of it inline. A likely-waiting-on derivation (idle agent
whose last direct message got no reply — honest heuristic) surfaces both on
Command and as dashed edges on the Map.

**Conversations depth**: direct-message threads (operator↔agent composable,
agent↔agent observable), the filterable trail
(sender/recipient/thread/record/urgency/body), and per-recipient post
receipts — watch a routed decision land, ingestion tick by ingestion tick.

**Mesh legibility**: `GET /api/mesh` (peers, live link state, relay health)
surfaced on the Map; the trust gate enforced at spawn (428 + the repo's
autorun surface until acknowledged); a global ⌘K palette.
